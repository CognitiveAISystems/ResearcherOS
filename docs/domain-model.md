# Доменная модель KOI

## Узлы и связи нового дерева

Начальным узлом может быть **тема**, **проблема**, **направление** или
**инженерное решение**. Тема необязательна. Метод — узел разработки и запуска кода;
его канбан содержит конкретные задачи и эксперименты.

| Родитель | Дочерние узлы | Связь |
|----------|---------------|-------|
| Тема | Проблема, направление, инженерное решение | Направление |
| Проблема | Метод, инженерное решение | Гипотеза с обязательной формулировкой или доказательство |
| Направление | Метод, инженерное решение | Направление |
| Инженерное решение | Метод, вложенное инженерное решение | Направление |

Связь «доказательство» обозначает получение свидетельств о проблеме,
а не утверждение, что она уже доказана. Слияние методов пока не поддерживается.
Узел «инженерное решение» внутри дерева отличается от программы лаборатории,
которая группирует несколько проектов в боковой панели.

У входящей связи есть `edge_type` (`direction`, `hypothesis`, `evidence`)
и `edge_label`. Они хранятся на дочернем узле, а в `project.md` — отдельной
служебным комментарием `<!-- koi:edge {"type": "hypothesis", "label": "Память уменьшит повторы"} -->`
перед заголовком узла. Отсутствующая строка означает обычную связь направления.

На карте гипотеза подписана на сплошной стрелке, доказательство показано
пунктирной стрелкой, направление — сплошной стрелкой с открытым наконечником.
Подпись связи открывает её редактор; неподписанную связь можно редактировать
через действие «Связь с родителем» у узла. В новом дереве можно выбрать тип
корня; у существующего корня он меняется в карточке, если дети совместимы.

Тема имеет лиловую овальную форму, проблема и направление — общий
рыжевато-розовый стиль, инженерное решение — сиренево-розовый, метод — голубовато-фиолетовый.

## Совместимость со старыми деревьями

В хранилище причины, гипотезы устранения и доказательства сохраняют свои узлы,
идентификаторы, описания и отчёты. На карте промежуточные причины скрываются, а их связи поднимаются к ближайшему
видимому родителю. Гипотезы и доказательства отображаются как подписанные связи.
Исходные причины доступны из карточки родителя и окна соответствующей связи. При одном методе
связь ведёт прямо к нему; при нескольких — к инженерному решению, которое ветвится на
методы. Пустая ветка также сохраняет инженерное решение для добавления первого метода.
Нажатие на подпись связи открывает исходную запись с описанием и отчётами.
Это проекция отображения, а не миграция данных; редактор старых записей сохраняет
исходные типы и правила добавления детей.

## Поток мышления (science agile)

```
Проблема
    ↓ «почему так?»
Причина (гипотеза о природе)
    ├→ Доказательство причины  ──→  Метод(ы)  ──→  [Канбан] ──→ Эксперименты
    └→ Гипотеза устранения     ──→  Метод(ы)  ──→  [Канбан] ──→ Эксперименты
```

В отличие от классического Agile (эпик → story → task), здесь нет «фич» — есть **вердикт** по узлу: гипотеза открыта, поддержана данными или опровергнута.

## Правила старой цепочки

| Родитель | Допустимые дети |
|----------|-----------------|
| — (корень проекта) | Проблема |
| Проблема | Причина |
| Причина | Доказательство причины, Гипотеза устранения |
| Доказательство / Устранение | Метод |
| Метод | — (эксперименты в канбане) |

## Канбан

- Привязан к узлу типа `method` (способ проверки гипотезы); у одной гипотезы может быть несколько методов.
- Создаётся автоматически при добавлении узла `method`.
- Карточки = планируемые или идущие эксперименты (не обязательно дублируют лист «Эксперимент» в дереве; в наброске связь опциональна через `linked_node_id`).
- Колонки по умолчанию: Backlog → Planned → Running → Done.

## Статусы гипотез (`verdict`)

- `open` — в работе
- `supported` — данные поддерживают
- `refuted` — опровергнута

В наброске вердикты заданы в модели, UI для смены статуса — следующий шаг.
